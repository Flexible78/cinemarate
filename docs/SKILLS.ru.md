# Что писать в скиллы и как это защищать

## Строки для CV / LinkedIn

- **Infrastructure as Code:** Terraform (провайдер Vercel), разделение
  «автоматизировано / осознанно вручную», документированный recovery drill.
- **CI/CD:** GitHub Actions - проверка синтаксиса функций и inline-скрипта,
  guard против коммита секретов; preview-окружение на каждый pull request,
  автодеплой из `main`.
- **Serverless / edge:** Vercel Functions, кэширование на CDN (`s-maxage`) как
  способ не упереться в лимиты внешнего API.
- **Secrets management:** ключи только на сервере, OIDC-доступ к хранилищу
  вместо статического токена, опциональный shared secret на эндпоинты.
- **Distributed data:** диагностика и устранение lost update - серверный merge
  с передачей базового состояния вместо last-write-wins.
- **Reliability:** таймаут на каждый внешний вызов, graceful degradation,
  прогрессивный рендеринг, health- и debug-эндпоинты.
- **LLM integration:** внешняя модель с фолбэком и валидацией ответа,
  hardening против prompt injection.
- **Observability (в планах, так и говорить):** log drain, SLO с алертами,
  ночной бэкап данных.

## Формулировки на собеседование

**«Расскажите про проект».** Сайт, которым я и жена пользуемся каждый день:
рейтинги из нескольких источников в одной карточке, общий список на два
устройства. Статический фронтенд, четыре serverless-функции, окружение описано
в Terraform, на каждый push - CI.

**«Какая была самая интересная проблема?»** Общий список терял записи. Клиент
присылал полное состояние и перезаписывал файл - кто сохранил последним, тот и
прав. Я перевёл запись на серверный merge: клиент присылает и элементы, и
ключи, которые он видел в прошлый раз, поэтому добавление с другого устройства
выживает, а удаление применяется только для того, что клиент действительно
видел.

**«Как вы работаете с секретами?»** Ни один ключ не лежит в репозитории:
переменные окружения проекта, доступ к хранилищу - через OIDC с
короткоживущим токеном. CI падает, если `.env` или строка, похожая на ключ,
попали в коммит.

**«Зачем тут Terraform, проект же маленький?»** Чтобы окружение можно было
воспроизвести и обсуждать в pull request, а не пересобирать по памяти в
дашборде. Отдельно зафиксировано, что автоматизировать пока нельзя, - это
честнее, чем притворяться, что автоматизировано всё.

**«Что бы вы сделали следующим шагом?»** Мониторинг и SLO с алертами, потом
автоматический бэкап списка, потом rate limit на функции.

**«Зачем в этом проекте ИИ?»** Чтобы закрыть настоящий бытовой вопрос «что
смотрим вечером» и показать безопасную интеграцию: ключ на сервере, таймаут,
фолбэк на локальный алгоритм, ответ модели валидируется, пользовательские
данные в промпте помечены как данные, а не инструкции.
